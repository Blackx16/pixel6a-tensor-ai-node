## 2. Android 17 (API Level 37) Platform Behavior Changes & Mitigations

### 2.1 Mandatory Local Network Permission (`ACCESS_LOCAL_NETWORK`)
* **Platform Rule**: Starting in [Android 17 (API level 37)](https://developer.android.com/about/versions/17/behavior-changes-17), Android enforces Local Network Protections across the entire networking stack—including Java `ServerSocket`, NIO `ServerSocketChannel`, and native POSIX sockets—blocking all inbound and outbound LAN traffic on local Wi-Fi subnets (`192.168.x.x`, `10.x.x.x`, `172.16.x.x`) by default ([Local Network Permission Guide](https://developer.android.com/privacy-and-security/local-network-permission)).
* **Design Decision**: We declare `<uses-permission android:name="android.permission.ACCESS_LOCAL_NETWORK" />` in `AndroidManifest.xml` and request it at runtime in `MainActivity.requestAndroid17PermissionsIfNeeded()` before binding the local Wi-Fi OpenAI server socket.

### 2.2 System-Enforced Per-App Memory Ceiling (`MemoryLimiter:AnonSwap`)
* **Platform Rule**: Android 17 enforces a strict per-app anonymous memory + ZRAM swap ceiling (`MemoryLimiter:AnonSwap`) scaled to device RAM across all apps regardless of `targetSdk` ([Android 17 All-Apps Behavior Changes](https://developer.android.com/about/versions/17/behavior-changes-all)). On a 6 GB Pixel 6a, loading a 2–3 GB model into anonymous heap (`malloc` / `RssAnon`) triggers immediate termination with `ApplicationExitInfo.REASON_OTHER` (`"MemoryLimiter:AnonSwap"`).
* **Design Decision**:
  1. **Read-Only `mmap` into File Page Cache (`RssFile`)**: In `tensor_affinity.cpp`, `mmapModelReadOnly()` maps model weight files with `mmap(nullptr, length, PROT_READ, MAP_SHARED, fd, 0)` and `madvise(addr, length, MADV_SEQUENTIAL)`. File-backed read-only pages reside in `RssFile` rather than `RssAnon` ([Why MMAP in llama.cpp Hides True Memory Usage](https://news.ycombinator.com/item?id=35426679)), allowing the Linux kernel (`kswapd`) to drop clean weight pages under pressure and fault them back in from the Pixel 6a's UFS 3.1 flash without counting against `MemoryLimiter:AnonSwap` ([Prima.cpp Page Cache Architecture](https://arxiv.org/html/2504.08791v2)).
  2. **Proactive Page Eviction on `onTrimMemory`**: Android 14+ deprecated fine-grained `TRIM_MEMORY_RUNNING_*` levels in favor of `TRIM_MEMORY_UI_HIDDEN` and `TRIM_MEMORY_BACKGROUND` ([Manage Your App's Memory](https://developer.android.com/topic/performance/memory/manage-app-memory)). When these fire, `TensorHardwareOptimizer.handleTrimMemory()` calls `madvise(addr, length, MADV_DONTNEED)` to return clean weight pages to the kernel immediately.
  3. **Single-Active-LLM Router Guardrail**: `UnifiedAiRouter` ensures that when switching between LiteRT (`gemma-4-E2B-it`) and ONNX (`Qwen2.5-1.5B-Instruct`), the previous engine's KV cache and native session are closed before the new engine initializes.

### 2.3 Foreground Service Types (`connectedDevice|specialUse`)
* **Platform Rule**: Android 15–17 restricts `dataSync` and caps `mediaProcessing` foreground services to 6 hours per 24-hour window before triggering `Service.onTimeout()` ([Foreground Service Types](https://developer.android.com/develop/background-work/services/fgs/service-types)).
* **Design Decision**: `AiHostForegroundService` uses `connectedDevice|specialUse` (`FOREGROUND_SERVICE_CONNECTED_DEVICE` and `FOREGROUND_SERVICE_SPECIAL_USE` with the mandatory `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE` manifest property) and holds a `WIFI_MODE_FULL_LOW_LATENCY` lock so the local Wi-Fi OpenAI endpoint remains reachable without timeout.

### 2.4 Lock-Free `MessageQueue`, Unmodifiable `static final` Fields & 16 KB Page Sizes
* **Lock-Free `MessageQueue`**: Apps targeting API 37 use Android 17's lock-free `android.os.MessageQueue` ([MessageQueue Behavior Change Guidance](https://developer.android.com/about/versions/17/changes/messagequeue)). We avoid any reflection on `MessageQueue` fields and perform all UI updates via lightweight main-thread coroutines.
* **Unmodifiable `static final` Fields**: Android 17 prohibits mutating `static final` fields via reflection or JNI `SetStatic*Field` ([Android 17 Target Behavior Changes](https://developer.android.com/about/versions/17/behavior-changes-17)). All JNI state in `TensorNativeBridge` is stored in non-final `@Volatile var` properties.
* **16 KB ELF Page Size Alignment**: Configured via `-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384` in `CMakeLists.txt` and dynamic `sysconf(_SC_PAGESIZE)` checks in `tensor_affinity.cpp` ([Support 16 KB Page Sizes](https://developer.android.com/guide/practices/page-sizes)).

## 3. Google Tensor GS101 & Mali-G78 MP20 Hardware Optimization

### 3.1 Big-Core Thread Pinning (`0xF0` CPU Affinity Mask)
* **Problem**: The Tensor GS101 pairs 2× out-of-order Cortex-X1 (`cpu6`–`cpu7`) and 2× out-of-order Cortex-A76 (`cpu4`–`cpu5`) cores with 4× in-order Cortex-A55 (`cpu0`–`cpu3`) cores ([DeviceInfo](https://www.deviceinfo.app/devices/google/pixel-6a/)). Running barrier-synchronized GEMV/GEMM matrix multiplication across all 8 cores causes the fast X1/A76 cores to stall at thread barriers waiting for the slow in-order A55 cores ([Voxel Android LLM Scheduling Analysis](https://devpost.com/software/voxel-17hezu?_gl=1*gkzu47*_gcl_au*ODgyMjI5ODYuMTc5MDc5NDAxMg..*_ga*MjEzMzkwMDU2Ny4xNzg0OTAxNTE4*_ga_0YHJK3Y10M*czE3OTA3OTQwMTIkbzEkZzEkdDE3OTA3OTQwNzIkajYwJGwwJGgw), [IREE Big/Little Scheduling Issue #7804](https://github.com/google/iree/issues/7804)). Furthermore, 4 threads saturate LPDDR4X/LPDDR5 memory bandwidth during `M=1` token decoding.
* **Solution**:
  - `TensorHardwareOptimizer.inferenceDispatcher` creates a 4-thread pool where every thread calls `sched_setaffinity` with mask `0xF0` (`cpu4`–`cpu7`, the 2× Cortex-A76 + 2× Cortex-X1 cores).
  - `TensorHardwareOptimizer.networkIoDispatcher` creates a 2-thread pool pinned to mask `0x0F` (`cpu0`–`cpu3`, the 4× Cortex-A55 cores) so HTTP socket parsing, SSE network writes, and disk downloads never steal cycles from the big cores.

### 3.2 Android Dynamic Performance Framework (`PerformanceHintManager`)
* **Problem**: The Linux `schedutil` DVFS governor on Tensor GS101 can take up to ~200 ms to ramp Cortex-X1 clocks when a burst of token generation starts ([Performance Hint API](https://source.android.com/docs/core/perf/performance-hint-api)).
* **Solution**: `TensorHardwareOptimizer` registers the 4 native thread IDs (`Process.myTid()`) with `PerformanceHintManager.createHintSession(tids, 25_000_000L)` and calls `reportActualWorkDuration()` after every generated token ([Performance Hint API Reference](https://developer.android.com/reference/android/os/PerformanceHintManager)).

### 3.3 Mali-G78 MP20 GPU Acceleration vs. Deprecated NNAPI
* **Why NNAPI is Avoided**: Android deprecated NNAPI in Android 15, and LiteRT v2 removed the NNAPI accelerator ([NNAPI Migration Guide](https://developer.android.com/ndk/guides/neuralnetworks/migration-guide), [LiteRT Migration Reference](https://developer.android.com/agents/skills/device-ai/litert/litert-runtime/references/migration)). On Android 15–17, Transformer `LayerNorm`/`GELU` ops on NNAPI fall back to slow reference CPU execution ([Mobile NPU Transformer Benchmark](https://tojohere.dev/blog/npu-transformer-guide.html)).
* **Unlocking Mali-G78 MP20 OpenCL on Android 17**: Android's linker namespace blocks `dlopen("libOpenCL.so")` unless the app manifest explicitly declares both `<uses-native-library android:name="libvndksupport.so" android:required="false" />` and `<uses-native-library android:name="libOpenCL.so" android:required="false" />` ([LiteRT-LM OpenCL Linker Issue #324](https://github.com/DenisovAV/flutter_gemma/issues/324), [LiteRT-LM Android Skill](https://developer.android.com/agents/skills/device-ai/litert/litert-lm/skill)). We declare both in `AndroidManifest.xml` so LiteRT (`Backend.GPU()`) runs directly on the 20-core Mali-G78 MP20 GPU, while ONNX Runtime uses the 4-thread ARM64 XNNPACK execution provider (`SessionOptions.addXnnpack`) ([ONNX Runtime Execution Providers](https://onnxruntime.ai/docs/execution-providers/)).
